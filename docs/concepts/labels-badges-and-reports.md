# Labels, badges and reports

Signoff produces three kinds of output so that declarations can be seen without reading `SIGNOFF.toml` or the git history: labels on pull requests, badges in the README, and reports for folders and releases.

## Labels on pull requests

The PR-signoff check validates the ticked AI declaration in the pull request template. It sets one label per axis:

| Label | Axis |
|---|---|
| `ai:G*` | Generation, for example `ai:G1` |
| `human:H*` | Human review, for example `human:H2` |
| `ai-review:A*` | AI review, for example `ai-review:A0` |

The labels appear once the declaration is valid. They follow the description: when you edit the ticked boxes, the check runs again. The workflow (`.github/workflows/pr-signoff.yml`) only runs for pull requests into `main`. See [declaring a pull request](../usage/declaring-a-pull-request.md) for how to tick the boxes.

## Badges

The README shows two rows of badges. Both are generated by workflows and stored as JSON files on the `badges` branch. The README displays them through shields.io endpoint URLs that read those files.

| Row | Counts | Files on the `badges` branch | Created by |
|---|---|---|---|
| First row: "Files and lines" | Files, or lines, at each level | `aisignoff-generation.json`, `aisignoff-human-review.json`, `aisignoff-ai-review.json` | File-signoff, on pushes to `main` |
| Second row: "Merged pull requests" | The declarations of pull requests merged into `main` | `ai-generation.json`, `ai-human-review.json`, `ai-review.json` | Signoff-Badges, on pushes to `main` |

### Files or lines

`file-signoff.yml` passes `weight: lines`, so the first row weights the badges by lines instead of files. Without that input, they count files. Because this repository turns on `[history]`, the line counts follow the line-level declarations (see [line-level declarations](line-level-history.md)).

### Merged pull requests

The second row summarises the declarations of merged pull requests. Until a declared pull request has been merged, these badges show "no declarations yet".

### The `badges` branch

The branch is created by the first push to `main` after setup. Do not protect it against pushes by `github-actions[bot]`, or the workflows cannot update the badges. See [setting up the repository](../getting-started/setup-on-github.md).

## Folder report

The File-signoff run on `main` produces a report of the level mix per folder, in two places:

- **Job summary:** the run's summary shows a folder tree with the levels.
- **Artifact:** the run uploads an artifact named `aisignoff-report`. Download and unzip it, then open the HTML page in a browser. It is an interactive folder report. The README points to it from the first badge row.

To find it, open *Actions → File-signoff*, choose the newest run on `main`, and look under *Artifacts*. Folders with a high generation level and a low human review level are the places where a second look is most useful.

`aisignoff-report.html` is listed in `.gitignore`, so a locally generated report is not committed by accident.

## Release reports

When a release is published, `signoff-release.yml` attaches three files to it, describing the code at the release tag:

| File | Content |
|---|---|
| `aisignoff-report.txt` | Summary per axis and the level mix per folder |
| `aisignoff-report.json` | Every file with its levels, names and source |
| `aisignoff-report.html` | The interactive folder report |

See [release reports and Zenodo](../usage/release-reports.md).

## Reports on the command line

The same information is available locally with `aisignoff report`. See [running aisignoff locally](../getting-started/local-commands.md).
